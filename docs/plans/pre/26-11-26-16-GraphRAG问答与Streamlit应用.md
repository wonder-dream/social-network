# 26-11-26-16 GraphRAG问答与Streamlit应用

## 目标
由同学 B（应用组）完成课程后 2 个实践环节：基于 Neo4j 子图检索的轻量级 GraphRAG 大模型增强问答、Streamlit + PyVis 交互式 Web 应用，以及 15~20 道常见病测试题的基线对比评测。

## 步骤
1. **并行联调准备**：在同学 A 交付完整 50 病图谱前，先用 3~5 种样例常见病数据导入本地 Neo4j，保证下游代码可立即开发测试。
2. **图谱检索模块**：基于官方 `neo4j` 驱动封装常用参数化查询（按疾病查症状/用药/检查/宜忌食物、按症状反查候选疾病、1~2 跳子图导出）。
3. **轻量 GraphRAG 问答链**：
   - 第一步：调大模型 JSON 模式从用户问题中抽取出疾病或症状实体，并经 `rapidfuzz` 匹配到图谱规范节点名；
   - 第二步：查出关联子图（上限 `LIMIT 30` 条三元组）转为结构化证据文本；
   - 第三步：构造 Grounded Prompt 要求大模型优先严格依据证据回答，未命中图谱时显式走兜底提示，所有输出统一附加健康科普免责声明。
4. **Streamlit 极简应用**：构建 2 个 Tab 页面：
   - Tab 1（图谱检索与可视化）：输入病名或症状，展示结构化关系表 + `pyvis` 交互式关系网络图；
   - Tab 2（智能问答）：聊天式问答界面，每条回复支持展开查看检索到的图谱三元组证据。
5. **基线对比评测**：构造 15~20 道测试题（含单跳属性、症状反查、饮食禁忌、未收录疾病兜底），对比“纯大模型”与“图谱增强（GraphRAG）”的输出并整理对比表与界面截图。

## 判据
- Web 界面可一键 `streamlit run app.py` 启动，两个 Tab 均可稳定演示无报错；
- 问答界面能清晰展示“命中图谱三元组 → 约束生成回答”的完整链路，未命中实体时正确触发兜底说明；
- 产出 15~20 题的基线对比记录表与至少 3~5 组直观对比案例截图。

## 取舍
- 不引入重型框架（如 Microsoft GraphRAG 全量社区摘要管线或复杂 LangChain 封装），用原生 Python + `neo4j` + `openai` 实现核心链路，代码量控制在 200 行左右，调试与答辩讲解成本最低。
