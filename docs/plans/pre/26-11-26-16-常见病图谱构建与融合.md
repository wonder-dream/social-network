# 26-11-26-16 常见病图谱构建与融合

## 目标
由同学 A（建图组）完成课程前 4 个实践环节：本体建模、50 种常见病双源数据获取与大模型抽取、多源知识融合、Neo4j 图数据库存储与可视化留痕，为同学 B 提供稳定可查的图谱实例。

## 步骤
1. **本体建模**：按 5 类实体（`Disease / Symptom / Drug / Check / Food`）与 5 类关系（`HAS_SYMPTOM / RECOMMEND_DRUG / NEED_CHECK / DO_EAT / NO_EAT`）使用 Draw.io 绘制本体结构图并保存至项目资源目录。
2. **确定 50 种常见病清单**：编写 `data/disease_list.txt`，覆盖呼吸、消化、心血管、代谢、皮肤、神经等高频常见病（如感冒、急性胃炎、高血压、2 型糖尿病、失眠、过敏性鼻炎等）。
3. **来源 A 清洗筛选**：下载 `QASystemOnMedicalKG` 的 `data/medical.json`，编写脚本筛选上述 50 种常见病并提取结构化三元组（`data/raw_source_a.json`）。
4. **来源 B 采集与 LLM 抽取**：调用中文维基百科 MediaWiki Action API 抓取其中 20~30 种常见病的纯文本摘要与症状/治疗段落；通过 `openai` SDK 调用 DeepSeek/Qwen（`json_object` + `temperature=0.0`）抽取符合本体的三元组（`data/raw_source_b.json`）。
5. **知识融合**：编写融合脚本，先做繁简/空格/括号规则清洗与 `alias_map.json` 同义词替换，再按实体类型用 `rapidfuzz`（`token_set_ratio >= 85`）对齐合并，输出融合统计报告与标准化 `data/nodes.csv`、`data/relations.csv`。
6. **Neo4j 入库**：安装 Neo4j Desktop 并创建本地库；使用官方 `neo4j` 驱动建立 5 个唯一约束，通过参数化 `UNWIND MERGE` 批量导入节点与关系，导出 Neo4j Browser 图谱截图用于技术报告。

## 判据
- 成功入库 50 种常见病，图谱规模稳定在 300~800 节点、800~2000 关系；
- 融合脚本输出清晰的融合前后实体/三元组统计对比表（至少产生可验证的跨源合并样本）；
- 导入脚本幂等（重复执行不产生重复节点/边），且 `MATCH (d:Disease)-[r]->(n) RETURN d,r,n LIMIT 50` 查询正常。

## 取舍
- 不爬取带验证码的反爬商业医疗站点，用维基百科官方 API 满足“数据爬取与清洗”要求；
- 不部署向量库做重型语义对齐，用“轻量同义词表 + RapidFuzz”控制融合复杂度，保证结果透明可解释。
