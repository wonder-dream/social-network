# 26-11-26 医疗 KG 数据与技术栈调研

## ① 威胁

1. **`py2neo` 弃用与兼容性陷阱**：中文教程中大量医疗图谱脚本仍依赖 `py2neo`，但该库已进入 End-of-Life 归档状态，不再支持新版 Neo4j 与现代 Bolt 协议，照抄旧教程容易卡死在驱动报错上。
2. **商业医疗网站反爬与数据脏乱**：直接爬取国内问诊/百科站点容易遭遇验证码、IP 封禁与繁琐 HTML 清洗，对 2 人速通课程作业性价比极低。
3. **非结构化抽取格式漂移与实体碎片化**：大模型直接输出自由文本难以解析；不同来源对同一疾病/症状表述不一（如“普通感冒/感冒”、“发热/发烧”），若不做实体对齐会导致图谱割裂。
4. **医疗问答安全与空检索幻觉**：医疗场景对编造用药建议容错率低；当用户问到 50 种常见病之外的病症时，若检索为空仍静默调用大模型，容易把模型自由发挥伪装成“图谱依据”。
5. **Cypher 注入与导入路径麻烦**：直接字符串拼接 Cypher 存在语法破坏与注入风险；使用 Neo4j `LOAD CSV` 需把文件手动放进 Neo4j `import/` 目录，两台电脑协作复现麻烦。

## ② 工具箱

### 开源医疗图谱数据集
- **`QASystemOnMedicalKG`**（`https://github.com/liuhuanyong/QASystemOnMedicalKG`）：
  - 核心数据文件为 `data/medical.json`，以疾病为中心的大宽表 JSON，包含 `name/desc/prevent/cause/symptom/check/common_drug/recommand_drug/do_eat/no_eat/acompany/cure_department`。
  - 适合直接筛选 50 种常见病作为结构化数据基底（来源 A）。
- **`CMeKG` / `CMeKG_tools`**：
  - 对标 ICD / SNOMED / ATC 等医学标准的中文医学知识图谱，含 30+ 类医学关系；完整商业库闭源，但其公开三元组与 NER/RE 标注范式适合作为本体设计与调研报告参考。

### 无反爬公开文本采集
- **中文维基百科 MediaWiki Action API**：`https://zh.wikipedia.org/w/api.php`（参数 `action=query&prop=extracts&exintro=true&explaintext=true&redirects=1&format=json`）或 Python 库 `Wikipedia-API`（`pip install Wikipedia-API`）。
- 官方鼓励通过 API 获取、无反爬机制，只需在请求头设置合规 `User-Agent` 并做适当延时即可作为双源融合的文本来源（来源 B）。

### 抽取、融合、存储与可视化工具栈
- **LLM 实体关系抽取**：`openai` SDK + `pydantic`，对接 DeepSeek / 通义千问 OpenAI 兼容端点，开启 `response_format={"type": "json_object"}` 与 `temperature=0.0`。
- **实体融合与去重**：`rapidfuzz`（`fuzz.token_set_ratio` + `process.extractOne`，同类型实体内比对，阈值 80~85）+ 手工轻量同义词表（`alias_map.json`）。
- **图数据库驱动**：官方 `neo4j` 包（`pip install neo4j`，`GraphDatabase.driver`），通过参数化 `UNWIND $rows AS row MERGE ...` 批量幂等写入，无需拷贝文件到 `import/`。
- **Web 应用与交互图谱**：`streamlit` + `pyvis`（生成交互式 HTML 网络图，通过 `streamlit.components.v1.html` 嵌入页面）。
