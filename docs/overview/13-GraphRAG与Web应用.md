# 13-GraphRAG与Web应用

## 轻量版 GraphRAG 问答链路（KG → LLM）

不依赖重型框架，核心链路约 60~100 行 Python，透明可控、便于写进技术报告：

1. **问题实体抽取**：将用户问题发送给大模型（JSON 模式，`temperature=0.0`），识别其中涉及的疾病或症状关键词，并与图谱中的规范实体名做精确/模糊匹配（`rapidfuzz`）。
2. **子图检索**：通过官方 `neo4j` 驱动执行参数化 Cypher，查询命中实体的 1~2 跳邻居（如症状 → 候选疾病 → 建议检查/常用药/饮食宜忌），限制返回三元组上限（如 `LIMIT 30`）防止上下文噪声过载。
3. **约束生成与兜底**：
   - 检索命中时：将结构化三元组拼为自然语言事实清单注入 System Prompt，要求大模型**优先严格基于图谱事实回答**，并列出引用的图谱依据；
   - 检索未命中时：显式提示“当前常见病图谱未收录该词条，以下为通用科普参考”，避免伪装成图谱结论；
   - 统一追加医疗免责声明。

## 智能应用界面（Streamlit）

- **Tab 1 · 图谱检索与可视化**：输入疾病或症状关键词，查询关联实体与关系表，并使用 `pyvis` 生成交互式节点关系图，通过 `streamlit.components.v1.html` 嵌入展示。
- **Tab 2 · 图谱增强智能问答**：对话式问答界面；每条回答下方附带可折叠的 `st.expander("查看检索到的图谱证据")`，直观展示命中三元组。

## 基线对比评测（60% 报告核心亮点）

准备 15~20 道常见病测试题（覆盖单跳属性查询、症状反查疾病、饮食忌口、多条件组合问题），用相同大模型对比：
- **Baseline**：纯大模型直接作答；
- **Ours**：轻量 GraphRAG（Neo4j 子图增强）作答。

记录回答事实一致性、是否编造/遗漏关键禁忌、证据可追溯性，整理成对比表格与典型案例截图写入技术报告。
