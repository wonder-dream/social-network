# 12-知识融合与图存储

## 知识融合方案（Entity Resolution）

由于来源 A（`medical.json`）与来源 B（维基百科经 LLM 抽取）在命名上存在口语/学名差异（如“发烧/发热”、“高血压/原发性高血压”、“感冒/普通感冒”），融合采用两阶段轻量流程：

1. **规则与词典归一化**
   - 统一繁简体、去空格与括号注释（如“阿莫西林（胶囊）” → “阿莫西林”）；
   - 维护一份轻量级常见病/症状同义词映射表（`alias_map.json`），将俗称映射到标准名。
2. **基于 RapidFuzz 的同类型模糊对齐**
   - 仅在同一实体类型内比对候选实体，使用 `rapidfuzz.process.extractOne` + `fuzz.token_set_ratio`（建议阈值 `85.0`）；
   - 命中阈值的实体合并到规范名称，保留属性并集（来源 A 属性优先，来源 B 补全缺失字段），按 `(head, relation, tail)` 精确去重。
3. **融合留痕指标（用于 60% 技术报告）**
   - 融合脚本需自动输出统计 JSON/表格：来源 A/B 各自实体与三元组数、合并实体对数、去重边数、融合前后压缩率。

## 知识存储（Neo4j）

- **驱动选型**：仅使用官方 `neo4j` 包（`pip install neo4j`），严禁使用已停止维护的 `py2neo`。
- **唯一约束**：导入前为 5 类节点建立 `name` 唯一性约束，确保幂等重跑不产生重复节点：
  ```cypher
  CREATE CONSTRAINT disease_name IF NOT EXISTS FOR (n:Disease) REQUIRE n.name IS UNIQUE;
  CREATE CONSTRAINT symptom_name IF NOT EXISTS FOR (n:Symptom) REQUIRE n.name IS UNIQUE;
  CREATE CONSTRAINT drug_name IF NOT EXISTS FOR (n:Drug) REQUIRE n.name IS UNIQUE;
  CREATE CONSTRAINT check_name IF NOT EXISTS FOR (n:Check) REQUIRE n.name IS UNIQUE;
  CREATE CONSTRAINT food_name IF NOT EXISTS FOR (n:Food) REQUIRE n.name IS UNIQUE;
  ```
- **批量导入**：通过 `driver.session()` 执行参数化 `UNWIND $rows AS row MERGE ...` 写入（比 `LOAD CSV` 少一步手动拷贝到 Neo4j `import/` 目录，跨机器复现更省心），同时导出标准 `nodes.csv` 与 `relations.csv` 留作数据归档。
