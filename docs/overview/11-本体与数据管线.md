# 11-本体与数据管线

## 本体层设计（Schema）

面向 50 种高频常见病（如感冒、胃炎、高血压、糖尿病、失眠、过敏性鼻炎等），保持精简且可读：

### 实体类型（5 类）
- `Disease`（疾病）：核心节点，属性包含 `name`、`desc`、`cause`、`prevent`、`source`
- `Symptom`（症状）：属性 `name`
- `Drug`（常用药）：属性 `name`
- `Check`（检查项目）：属性 `name`
- `Food`（食物）：属性 `name`

### 关系类型（5 类）
- `(:Disease)-[:HAS_SYMPTOM]->(:Symptom)`（典型症状）
- `(:Disease)-[:RECOMMEND_DRUG]->(:Drug)`（参考常用药）
- `(:Disease)-[:NEED_CHECK]->(:Check)`（建议检查）
- `(:Disease)-[:DO_EAT]->(:Food)`（宜吃食物）
- `(:Disease)-[:NO_EAT]->(:Food)`（忌吃食物）

*(注：如需补充并发症，可选扩展 `(:Disease)-[:ACCOMPANY_WITH]->(:Disease)`。)*

## 双源数据采集

1. **来源 A（结构化基底）**：从开源项目 `QASystemOnMedicalKG` 的 `data/medical.json` 中筛选 50 种常见病记录，解析其 `symptom`、`common_drug`/`recommand_drug`、`check`、`do_eat`、`no_eat` 字段。
2. **来源 B（非结构化爬虫文本）**：通过中文维基百科官方 **MediaWiki Action API**（`https://zh.wikipedia.org/w/api.php` 或 `Wikipedia-API` 库）抓取其中 20~30 种常见病的纯文本摘要与症状/治疗段落，设置规范 `User-Agent` 与请求延时（`0.5~1s`），合法且零反爬。

## 大模型实体与关系抽取（LLM → KG）

- 依赖：`openai` Python SDK + `pydantic`，对接 DeepSeek / 通义千问兼容接口。
- 关键参数：`response_format={"type": "json_object"}`，`temperature=0.0`。
- 输出约束：严格限定只抽取本体中的 5 类实体与 5 类关系，过滤无效/空值字段，输出标准三元组列表 `(head, head_type, relation, tail, tail_type, source)`。
